# Supporting use-case scenarios

These brief scenarios cover the non-critical goals. The three selected critical cases are fully dressed in [scenarios.md](scenarios.md). All goals inherit authenticated role/scope checks, input validation, atomic writes and audit guarantees from [operation-contracts.md](operation-contracts.md). Failure never silently advances the workflow or exposes protected clinical data.

| Use case | Trigger / actor | Main success scenario | Alternate or failure scenario | Operations |
|---|---|---|---|---|
| UC01 Manage Patient Registration | Staff receives a new patient or corrected demographics | Staff searches for duplicates, confirms identity, enters demographics and optional coverage details; system creates a unique patient and clinical record or updates the existing patient's editable data | Ambiguous match requires confirmation; malformed birth date/coverage or confirmed duplicate rejects creation; no fabricated insurance number required | O01, O10–11 |
| UC02 Search Patient | Authorized user needs to identify a patient | Enter insurance number, birth date, phone or partial first/last name; system returns minimum matching identity information; user verifies the intended person | No matches returns empty result; multiple matches require disambiguation; a patient cannot enumerate other patients | O01 |
| UC04 Confirm Appointment | Patient/self or staff receives agreement to a requested appointment | Select requested appointment; system validates authority/state and reservation, changes status to confirmed and returns confirmation | Cancelled/completed appointment or invalid reservation rejected; no false confirmation | O12 |
| UC05 Reschedule Appointment | Patient/self or staff requests a different time | Search availability, select a replacement professional/location/time for the same service, submit; system revalidates and atomically replaces the reservation | Slot taken or referral invalid: retain old reservation; arrived/completed/cancelled booking cannot move | O02, O13 |
| UC06 Cancel Appointment | Patient/self or staff requests cancellation | Select unarrived requested/confirmed booking; system marks cancelled, releases capacity and preserves history | Unauthorized request, already cancelled or arrived/completed booking rejected; never delete the booking | O14 |
| UC09 View Clinical Record | Authorized professional needs clinical history | Identify patient, system checks care scope and audit availability, records the access and returns permitted clinical information | Administrative user or professional outside care scope is denied; no clinical content appears in error/audit payload | O06 |
| UC10 Issue Prescription | Authorized prescriber decides medication is appropriate after consultation | Select recorded consultation, enter one or more existing medications with dosage/instructions; system validates and records prescription/items linked to issuer and consultation | No prescribing privilege, empty items, missing medication or dosage rejects entire prescription; consultation remains recorded; no pharmacy transmission | O08 |
| UC11 Request Follow-up Appointment | Treating professional determines follow-up is needed | From recorded consultation, search availability and submit follow-up booking; system revalidates schedule/referral and creates requested appointment linked to consultation | No slot/required referral: no follow-up appointment; original consultation remains; clinician may retry later | O02, O09 |
| UC12 Issue/Record Referral | Professional decides on referral, or staff receives an external referral | Identify patient and referring professional; enter requested specialty/professional, reason and priority; system records active referral; external referrer need not practise at clinic | Neither target provided, incompatible targets or unauthorized staff originating a clinical decision is rejected; staff may transcribe an existing received referral only | O15; O17 if external referrer must first be registered |
| UC13 Update Referral Status | Authorized user receives referral progress/cancellation | Select referral and permitted closed/cancelled status; system validates and records transition, retaining history | Invalid transition or unresolved requested/confirmed appointments blocks update until bookings are explicitly resolved | O16 |
| UC14 Manage Professional Profile | Authorized staff onboards/updates a professional or clinic catalogue | Maintain clinic locations and specialties, then professional identity/type/licence/specialties/practice sites/qualified service IDs; external referrer may have no practice site | Invalid references or change invalidating future bookings rejected; cannot silently delete relationships used by reservations | O17–19 |
| UC15 Manage Schedule | Authorized professional/staff sets working availability and services | Maintain service duration/referral/coverage metadata, select professional and location, enter effective weekly intervals/service eligibility; system stores valid schedule | Invalid interval, ineligible location/service, conflicts or invalidation of existing bookings rejected | O20–21 |
| UC16 Record Fees and Generate Invoice | Staff bills applicable uninsured services | Select appointment, manually assess actual patient/service coverage and record outcome/basis; for an uninsured outcome record fee(s), then select this patient's uninvoiced fees; system creates invoice with sum total and unpaid status (zero total is paid) | Negative fee, RAMQ-covered or undetermined coverage outcome, absent assessment basis, mixed patients or previously invoiced fee rejects action | O22–23 |
| UC17 Register Payment | Staff verifies receipt of direct/private-insurance payment | Select invoice, enter positive amount and method/reference; system creates payment and updates derived balance/status, allowing partial payment | Overpayment/nonpositive amount or forbidden role rejected; no payment-gateway request is made | O24 |
| UC18 Review Audit Trail | User with dedicated audit permission investigates activity | Enter bounded date/actor/action filters; system returns metadata-only events and logs the review itself | Ordinary staff without audit permission denied; invalid filters/audit unavailability return controlled failure | O25 |

No supporting goal is dropped because it is classified non-critical. Clinical prescription/referral authority, precise billing rules and identity provisioning remain confirmation items, not implied implemented integrations.
